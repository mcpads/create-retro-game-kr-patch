# Mega Drive 국소 사례

## MD-001

- **관측 범위:** Mega Drive 마도물어의 이벤트 스크립트.
- **사고 맥락:** 번역 과정에서 대화 종료와 컷신 종료 코드가 빠진 항목은 버튼을 눌러도 진행하지 않는 soft lock으로 이어졌다. 반대로 선행판이 인라인 내용을 다음 엔트리로 나눈 경우에는 단순 집합 비교가 누락으로 오인했다.
- **결정 실험:** 원본·번역의 제어코드를 엔트리별로 전수 비교하고, 종료 코드가 없으면 치명 실패로 분류하되 인접 엔트리의 분할 구조까지 확인해 오탐을 걸렀다.
- **확정 결론:** 제어코드 보존 검사는 빌드 게이트가 될 수 있지만 엔트리 경계를 모르는 집합 비교만으로 자동 수정하지 않는다.
- **전이 한계:** 제어코드 집합 일치는 순서·인자·런타임 의미까지 증명하지 않는다.
- **관련 판단 기준:** `references/strategy/build-and-verify.md` §5, `references/strategy/text-extraction.md` §2.

## MD-003

- **관측 범위:** Mega Drive 마도물어의 16×16 가변폭 글리프 데이터와 해당 글리프 선택 소비자.
- **사고 맥락:** 글리프마다 비슷한 256바이트 블록 네 개가 이어져 중복 데이터나 넓은 캔버스의 미사용 영역처럼 보였다. 한 복사본만 생성하면 정렬 위치에 따라 글자가 사라지거나 잘릴 수 있었다.
- **검증 근거:** 소비자 디스어셈블리에서 현재 X 좌표의 하위 2비트가 네 복사본 중 하나를 고르는 것을 확인했다. 현행 폰트 빌드는 글리프를 0·1·2·3픽셀 왼쪽으로 각각 옮긴 네 블록을 생성해 원본과 같은 1024바이트 구조를 만든다.
- **확정 결과:** 반복처럼 보인 네 블록은 가변폭 블리팅의 정렬 상태를 위한 사전 시프트 복사본이었으며, 이 경로에서는 네 상태를 모두 생성해야 했다.
- **전이 한계:** 다른 렌더러는 복사본 선택식·합성 방식·좌표 단위를 추적해 필요한 시프트 상태를 다시 산정한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/runtime-assets.md`, `references/strategy/debugging.md`.
