# Alternate name producers bypassed canonical encoding

- **Search terms:** empty name, default nickname, temporary battle record, mixed ASCII Hangul, name changes after transition
- **Observed scope:** Default names and Diary-to-battle nickname transport in a PlayStation game.
- **Failure context:** Keyboard-entered names worked, but confirming an empty field copied legacy defaults into repurposed glyph codes. Separately, a corrected preparation screen was followed by a battle producer that copied the old display companion again, corrupting valid English, digit and symbol names.
- **Discriminating evidence:** Comparing canonical and companion words across transitions exposed the divergent writers. Native empty confirmation identified the default copier; a battle-record write breakpoint identified a later producer after the preparation correction.
- **Established result:** Defaults encoded through the existing canonical mapping survived empty confirmation and classroom entry. Temporary battle names were resolved from canonical Diary words through the shared mapping; actual battle, pause and return preserved the observed nickname, with additional controlled mixed-name and registered-name regressions.
- **Transfer limit:** Trace applicable default, import, registration and temporary-record writers to the matching canonical record and conversion boundary. Existing corrupted saves require separate recovery; controlled display fixtures establish only downstream consumption.
