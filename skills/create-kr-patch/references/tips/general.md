# 여러 플랫폼의 국소 사례

## DC-003

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 옵션·일시정지 라벨.
- **사고 맥락:** 옵션 세그먼트 메타데이터의 일본어 라벨을 믿고 번역했지만 실제 화면의 타일 인덱스가 나타내는 문구와 달랐다. 추정한 표시 경로를 제거해도 잘못된 표시는 남았다.
- **결정 실험:** 세그먼트의 타일 인덱스를 바이너리에서 직접 디코드하고 조합 순서를 다시 따라가 잘못 붙은 라벨을 교정했다.
- **확정 결론:** 사람이 붙인 추출 라벨은 원문 증거가 아니었다. 이 사례에서는 실제 화면이 읽은 타일 데이터로 잘못된 라벨을 교정했다.
- **전이 한계:** 제거 실험이 입력 데이터나 조합 순서도 함께 바꾸면 라벨 오류를 분리하지 못한다.
- **관련 판단 기준:** `references/strategy/debugging.md` §2·§6, `references/strategy/text-extraction.md`.

## DC-004

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 추가 라벨 테이블 배치와 Saturn판 와쿠와쿠 뿌요뿌요 던전의 코드 삽입 공간 조사.
- **사고 맥락:** Dreamcast에서는 0으로 채워지고 다른 패치와 겹치지 않는 범위를 빈 공간으로 보았지만, 저장 데이터가 없는 상태에서 처음 부팅하자 게임이 멈췄다. Saturn에서는 직접 호출과 값 참조가 발견되지 않은 함수 영역을 후보로 골랐지만 던전 진입 때 간접 호출됐다.
- **결정 실험:** Dreamcast의 첫 잘못된 명령을 추적하자 패치 데이터가 문자 변환 코드와 상수를 덮은 사실이 드러났다. 원본 코드를 복원하고 서로 연결된 세 데이터 표를 한 단위로 옮겨 모든 참조를 갱신한 빌드는 빈 저장 장치의 첫 부팅, 옵션 화면과 스토리를 통과했다. Saturn은 후보마다 진입 시 멈추는 빌드를 따로 만들어 같은 플레이 경로를 실행했다. 실제 진입이 확인된 범위는 제외하고, 미진입 후보도 관측한 경로 안에서만 미도달로 기록했다.
- **확정 결과:** 0 채움과 정적 참조 부재는 두 사례에서 미사용 공간의 증거가 아니었다. 실행이 관측되면 사용 중임을 확정할 수 있었지만, 제한된 플레이에서 실행되지 않았다는 사실은 다른 경로의 미사용까지 증명하지 못했다.
- **전이 한계:** 관측하지 않은 모드·경로·후반 구간이 남으면 코드·데이터 삽입 공간 판정도 그만큼 제한된다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §5, `references/strategy/initial-survey.md`, `references/conventions/project-conventions.md` §5.2.

## GG-002

- **관측 범위:** Game Gear 마도물어 1의 상점·HUD 돈 단위 글리프와 장면 초기 VRAM 전송.
- **사고 맥락:** ROM의 글리프 후보를 바꿔도 표시가 그대로여서 실제 글리프가 압축됐거나 실행 중 생성된다고 결론냈다. 그러나 실험은 이전 VRAM이 남은 저장 상태를 불러와 초기 전송을 건너뛴 상태였다.
- **결정 실험:** 부팅부터 VRAM 쓰기를 관측해 원본 주소와 메모리 매핑 상태를 ROM 후보에 연결했다. 수정 ROM을 처음부터 다시 실행하자 후보 중 하나가 돈 타일의 ROM 내 원본임이 확인됐다.
- **확정 결론:** 초기 전송을 건너뛴 저장 상태 때문에 실제 ROM 글리프 위치를 잘못 기각한 사례였다.
- **전이 한계:** 저장 상태는 이후 장면을 재현할 수 있지만 생략된 적재·전송·캐시 갱신의 부재를 증명하지 않는다.
- **관련 판단 기준:** `references/strategy/runtime-assets.md` §2, `references/strategy/debugging.md` §2.

## GG-003

- **관측 범위:** Game Gear 마도물어 1의 초기 일본어 디코딩과 그 결과를 기준으로 만든 한국어 번역 자산.
- **사고 맥락:** 구 디코더가 원시값 `0x7F`를 별표로 읽었지만 원문·화면 대조에서 이 값은 일본어 온점 `。`으로 확인됐다. 디코더와 추출 원문만 고친 뒤에도 기존 한국어 번역에는 별표와 잘못된 해석이 대량으로 남았다.
- **결정 실험:** 대상 ROM의 빈도·문맥, 실제 화면 표본과 다른 버전의 원문을 대조해 온점을 확정했다. 한국어 별표의 위치도 전수 조사한 뒤 영향 범위를 재번역하고 교차 검토했다.
- **확정 결론:** `0x7F`는 이 경로에서 일본어 온점이었고, 구 디코딩을 보고 만든 번역은 디코더 수정만으로 고쳐지지 않았다. 영향받은 번역을 다시 대조해 바로잡았다.
- **전이 한계:** 특정 문자 검색만으로 이전 기준으로 만든 번역을 판정하지 않고 원문 식별 정보와 디코딩 변화의 영향 범위를 비교한다.
- **관련 판단 기준:** `references/conventions/translation-artifacts.md` §1·§5, `references/strategy/translation-workflow.md` §3.1.

## MD-002

- **관측 범위:** Mega Drive 마도물어 1의 초기 한국어 대화 번역.
- **사고 맥락:** 일본어 원문과 선행 영어 번역은 네 화자 전환을 보존했지만, 초기 한국어 번역은 이를 한 사람의 독백처럼 합쳐 화자·말투·질문 응답 관계를 잃었다.
- **결정 실험:** 일본어·영어·한국어 문장 정렬과 이벤트의 화자 제어 순서를 함께 대조해 구조 손실이 초기 한국어 번역에서 생겼음을 확인하고 네 차례의 화자 전환을 복원했다.
- **확정 결론:** 초기 한국어 번역이 원본의 화자 전환을 잃어 질문·응답 관계와 말투가 어긋난 사례였다.
- **전이 한계:** 영향 범위는 화자 제어 순서가 달라진 항목으로 정하고 원문과 다시 대조한다.
- **관련 판단 기준:** `references/strategy/translation-workflow.md` §2.4.

## SATURN-003

- **관측 범위:** Saturn 마도물어의 CNX v2 압축 전투 자산.
- **사고 맥락:** 한국어 빌드에서 전투 애니메이션이 깨졌다. 파일 제외 실험은 원인 자산을 좁혔지만 번역 데이터 차이가 없고 자체 압축·해제 왕복도 통과해 다른 원인을 의심했다.
- **결정 실험:** 일본어판 원본의 해제 데이터를 고치지 않고 같은 압축기로 재압축한 ROM에서도 결함이 재현됐다. 자체 왕복은 계속 통과했으므로 압축기와 게임 해제기의 의미 차이를 조사했다.
- **확정 결과:** 압축기는 아직 출력되지 않은 0 초기화 구간까지 일치 후보로 허용했지만 게임 해제기는 이미 출력된 범위만 안전하게 역참조할 수 있었다. 참조 거리를 출력 완료 범위로 제한해 수정했다.
- **전이 한계:** 자체 왕복은 대상 해제기 호환성을 보장하지 않는다. 무수정 재압축물도 실제 소비자에서 검증한다.
- **관련 판단 기준:** `references/strategy/compression.md` §4, `references/strategy/debugging.md` §2.

## SATURN-005

- **관측 범위:** Saturn 마도물어의 전투 메뉴 탭.
- **사고 맥락:** 메뉴를 열 때 VRAM 쓰기가 없고 주 폰트를 바꿔도 일본어 탭이 남아 표시 시점 생성과 주 폰트 표시 가설이 기각됐다.
- **결정 실험:** 해제한 스프라이트 자산에서 선택·비선택 상태의 라벨 쌍을 직접 디코드해 화면과 대응시켰다. 두 상태를 모두 교체한 빌드에서 전체 탭이 바뀌었다.
- **확정 결론:** 실제 수정 단위는 주 폰트가 아니라 미리 적재된 두 상태의 스프라이트 이미지였다.
- **전이 한계:** 표시 시점의 쓰기가 없다는 사실만으로 미리 적재된 파일이나 오프셋을 확정할 수는 없다. 저장 자산의 디코드와 표시 결과를 연결해야 한다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §1, `references/strategy/runtime-assets.md` §2.

## SATURN-007

- **관측 범위:** Saturn 마도물어에서 글리프 수 제한 때문에 번역 표현을 바꾼 사례.
- **사고 맥락:** 미할당 음절 때문에 `부숴`를 `부셔`로 쓰는 등의 표현 절충이 번역 데이터에 들어갔다. 그대로 두면 기술 제약이 번역 의도처럼 굳을 위험이 있었다.
- **결정 실험:** 출현 횟수와 실제로 줄어드는 고유 글리프 수를 따로 계산하고, 각 후보의 의미·말투 손실을 검토했다.
- **확정 결론:** 맞춤법 손실이 큰 표현은 복원하고, 자연스러운 대체 표현으로 실제 고유 글리프 수가 줄어드는 경우만 절충 대상으로 남겼다. 각 절충에는 원래 의도와 필요한 글리프를 기록했다.
- **전이 한계:** 표현 축소는 현재 설계에서 글리프 공급을 늘릴 수 있는지 먼저 확인하고, 번역 전체에서 실제로 줄어드는 글리프 수와 의미 손실을 사람이 검토한 경우에만 선택한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §3.2, `references/strategy/translation-workflow.md` §4, `references/conventions/project-records.md`.

## SNES-006

- **관측 범위:** SNES 나조뿌요 1의 누적 로고와 PC Engine CD 마도물어 1의 컷신 자막이 후속 원본 쓰기에 덮인 사례.
- **사고 맥락:** SNES에서는 중간 해제 조각 뒤에 한국어를 덮어쓰자 후속 조각이 로고 일부를 다시 덮었다. PC Engine에서는 선행 구현의 자막 쓰기만 재현해 같은 영역의 원본 자동 전송이 계속 자막을 덮었다.
- **결정 실험:** 같은 VRAM 영역을 건드리는 모든 쓰기를 추적했다. SNES는 마지막 전송 뒤에 한국어를 덮어썼고, PC Engine은 표시 중 계속 충돌하는 자동 전송만 억제해 한국어 자막과 나머지 화면을 모두 유지했다.
- **확정 결론:** 새 쓰기를 추가해도 뒤의 원본 쓰기는 사라지지 않았다. 마지막 쓰기 뒤에 적용하거나 충돌하는 기존 쓰기만 확인된 범위에서 억제해야 했다.
- **전이 한계:** 다른 장면은 모든 쓰기의 주소·시점·화면 수명을 다시 추적하고, 충돌하지 않는 원본 갱신까지 함께 끄지 않는다.
- **관련 판단 기준:** `references/strategy/runtime-assets.md` §2, `references/strategy/reinsertion.md` §4.

## SNES-008

- **관측 범위:** SNES 나조뿌요 1(룰루의 루)의 타일 손상 원인 가설.
- **사고 맥락:** 뿌요 타일이 한글 글리프로 깨졌고, 여러 시점의 관측이 VRAM 쓰기와 관련된 훅을 원인으로 본 가설과 맞아떨어졌다.
- **결정 실험:** 그 훅만 제거한 빌드에서 증상이 그대로여서 가설을 기각했다. 이후 DMA 소스 추적으로 게임이 쓰는 WRAM 영역을 한글 폰트가 덮은 것이 실제 원인임을 확정했다.
- **확정 결론:** 원인은 의심한 훅이 아니라 한글 폰트가 게임의 WRAM 영역을 침범한 것이었다.
- **전이 한계:** 제거가 다른 경로까지 바꾸면 기각 실험으로 사용할 수 없다.
- **관련 판단 기준:** `references/strategy/debugging.md` §2.

## SNES-015

- **관측 범위:** SNES 나조뿌요 1 한글 폰트 빌드에서 비트맵 글리프를 내장하고 윤곽선 데이터가 사실상 비어 있는 폰트 입력을 처리한 래스터화 경로.
- **사고 맥락:** 폰트 파일 파싱은 성공했지만 한글 글리프를 래스터화한 결과가 0×0으로 반환돼, 빌드가 빈 폰트 페이지를 만들 수 있었다.
- **검증 근거:** 입력 폰트의 비트맵 테이블과 사실상 빈 윤곽선 데이터를 확인하고 첫 한글 글리프의 비트맵 크기와 전체 빈 글리프 수를 검사했다. 같은 계열의 윤곽선 기반 폰트는 실제 픽셀을 반환했다.
- **확정 결과:** 이 입력과 래스터 경로에서는 파일 파싱에 성공해도 빈 글리프 자산이 만들어질 수 있었고, 대표 글리프 크기와 전체 빈 글리프 수 검사로 이를 차단했다.
- **전이 한계:** 폰트 데이터 구성·대상 코드 포인트·래스터 구현이나 경로가 바뀌면 대표 글리프 검사를 반복한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §4·§6, `references/conventions/project-conventions.md` §4·§5.3.

## NES-001

- **관측 범위:** NES 파로디우스다!의 선행 영어 패치 분석용 이미지.
- **사고 맥락:** 선행 패치는 확장 데이터를 PRG-RAM에 두고 실제로 읽었지만 이미지 헤더는 PRG-RAM이 없다고 선언했다. 정상 진행 뒤 매핑되지 않은 값을 명령으로 실행하며 정상 제어 흐름을 벗어났다.
- **결정 실험:** 처음 정상 제어 흐름을 벗어난 지점을 추적한 뒤 분석용 사본의 PRG-RAM 선언만 고쳤다. 같은 진행 경로가 계속 이어져 헤더 선언 불일치가 실패에 영향을 준다는 사실을 확인했다.
- **확정 결론:** 헤더 수정은 선행 패치 조사용 사본에만 필요했고, 일본어 원본을 입력으로 한 패치에 적용할 근거는 없었다.
- **전이 한계:** 선언 교정은 이 문제의 원인만 분리하며 선행 패치 전체의 정확성이나 실제 패치 입력의 헤더를 바꿔야 함을 증명하지 않는다.
