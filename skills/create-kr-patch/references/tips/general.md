# 공통 판단 사례

## DC-002

- **관측 범위:** Dreamcast·SNES·Game Gear·Saturn의 공용 글리프·타일 슬롯과 PlayStation의 이름 입력·날짜 표시가 공유한 숫자 글리프.
- **사고 맥락:** 한 화면만 보고 슬롯의 의미를 바꾸자 같은 슬롯을 읽는 다른 라벨·장식·숫자 표시가 깨졌다. PlayStation에서는 이름 입력 후보의 숫자 코드를 바꾸자 같은 코드를 쓰는 월·일 표시까지 손상됐다.
- **결정 실험:** 슬롯을 읽는 소비자를 열거하고 새 슬롯과 참조를 함께 갱신하거나 공유 픽셀을 보존했다. PlayStation은 날짜 표시가 읽는 숫자 코드를 유지하고 나머지 이름 입력 후보만 바꿔 두 화면을 함께 확인했다.
- **확정 결론:** 물리 슬롯은 처음 발견한 화면만의 자산이 아니었다. 공유 소비자를 확인하지 않은 슬롯 재배정은 다른 표시를 손상시킬 수 있었다.
- **전이 한계:** 새 자산에서는 같은 슬롯을 읽는 표시와 비텍스트 경로를 다시 열거하고, 확인된 공유 관계에 맞춰 새 슬롯 배정·공통 픽셀 보존·참조 갱신 가운데 필요한 처리를 고른다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §2·§5, `references/strategy/graphics-text.md` §2·§3, `references/strategy/runtime-assets.md` §2, `references/strategy/build-and-verify.md` §4.

## DC-003

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 옵션·일시정지 라벨.
- **사고 맥락:** 옵션 세그먼트 메타데이터의 일본어 라벨을 믿고 번역했지만 실제 화면의 타일 인덱스가 나타내는 문구와 달랐다. 추정한 표시 경로를 제거해도 잘못된 표시는 남았다.
- **결정 실험:** 세그먼트의 타일 인덱스를 바이너리에서 직접 디코드하고 조합 순서를 다시 따라가 잘못 붙은 라벨을 교정했다.
- **확정 결론:** 사람이 붙인 추출 라벨은 원문 증거가 아니었다. 이 사례에서는 실제 화면이 읽은 타일 데이터로 잘못된 라벨을 교정했다.
- **전이 한계:** 제거 실험이 입력 데이터나 조합 순서도 함께 바꾸면 라벨 오류를 분리하지 못한다.
- **관련 판단 기준:** `references/strategy/debugging.md` §2·§6, `references/strategy/text-extraction.md`.

## DC-004

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 추가 라벨 테이블 배치와 Saturn판 와쿠와쿠 뿌요뿌요 던전의 코드 삽입 공간 조사.
- **사고 맥락:** Dreamcast에서는 0으로 채워지고 다른 패치와 겹치지 않는 범위를 빈 공간으로 보았지만, 저장 데이터가 없는 상태에서 처음 부팅하자 게임이 멈췄다. Saturn에서는 직접 호출과 값 참조가 발견되지 않은 함수 영역을 후보로 골랐지만 던전 진입 때 간접 호출됐다.
- **결정 실험:** Dreamcast의 첫 잘못된 명령을 추적하자 패치 데이터가 문자 변환 코드와 상수를 덮은 사실이 드러났다. 원본 코드를 복원하고 서로 연결된 세 데이터 표를 한 단위로 옮겨 모든 참조를 갱신한 빌드는 빈 저장 장치의 첫 부팅, 옵션 화면과 스토리를 통과했다. Saturn은 후보마다 진입 시 멈추는 빌드를 따로 만들어 같은 플레이 경로를 실행했다. 실제 진입이 확인된 범위는 제외하고, 미진입 후보도 관측한 경로 안에서만 미도달로 기록했다.
- **확정 결과:** 0 채움과 정적 참조 부재는 두 사례에서 미사용 공간의 증거가 아니었다. 실행이 관측되면 사용 중임을 확정할 수 있었지만, 제한된 플레이에서 실행되지 않았다는 사실은 다른 경로의 미사용까지 증명하지 못했다.
- **전이 한계:** 관측하지 않은 모드·경로·후반 구간이 남으면 코드·데이터 삽입 공간 판정도 그만큼 제한된다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §5, `references/strategy/initial-survey.md`, `references/conventions/project-conventions.md` §5.2.

## GG-002

- **관측 범위:** Game Gear의 장면 초기 VRAM 전송과 SNES의 장면 시작 때 한 번만 기록되는 스크롤 배너.
- **사고 맥락:** 이전 VRAM이 남은 저장 상태나 화면이 나타난 뒤의 중단점으로 관측해, 실제 원본 후보와 쓰기 경로를 기각했다. 두 경로 모두 관측을 시작하기 전에 적재·쓰기가 끝났다.
- **결정 실험:** 부팅 또는 장면 진입 전부터 쓰기를 관측하고, 수정 원본이 적재·전송되는 경로를 소비자까지 대조했다.
- **확정 결론:** 저장 상태와 늦게 건 중단점은 이미 끝난 일회성 적재·쓰기의 부재를 증명하지 못했다.
- **전이 한계:** 캐시·VRAM을 재사용하는 화면은 적재·쓰기 시점보다 앞에서 관측을 시작하고, 저장 상태는 이후 소비 경로 재현에만 쓴다.
- **관련 판단 기준:** `references/strategy/runtime-assets.md` §2, `references/strategy/debugging.md` §2.

## GG-003

- **관측 범위:** Game Gear 마도물어 1의 초기 일본어 디코딩과 그 결과를 기준으로 만든 한국어 번역 자산.
- **사고 맥락:** 구 디코더가 원시값 `0x7F`를 별표로 읽었지만 원문·화면 대조에서 이 값은 일본어 온점 `。`으로 확인됐다. 디코더와 추출 원문만 고친 뒤에도 기존 한국어 번역에는 별표와 잘못된 해석이 대량으로 남았다.
- **결정 실험:** 대상 ROM의 빈도·문맥, 실제 화면 표본과 다른 버전의 원문을 대조해 온점을 확정했다. 한국어 별표의 위치도 전수 조사한 뒤 영향 범위를 재번역하고 교차 검토했다.
- **확정 결론:** `0x7F`는 이 경로에서 일본어 온점이었고, 구 디코딩을 보고 만든 번역은 디코더 수정만으로 고쳐지지 않았다. 영향받은 번역을 다시 대조해 바로잡았다.
- **전이 한계:** 특정 문자 검색만으로 이전 기준으로 만든 번역을 판정하지 않고 원문 식별 정보와 디코딩 변화의 영향 범위를 비교한다.
- **관련 판단 기준:** `references/conventions/translation-artifacts.md` §1·§5, `references/strategy/translation-workflow.md` §3.1.

## GG-007

- **관측 범위:** Game Gear의 영문 기반 엔진과 NES 일본어판이 같은 raw byte를 서로 다른 토큰 의미로 소비한 경로.
- **사고 맥락:** 선행 자료의 변수·문장부호 토큰을 숫자 그대로 보존했지만, 대상 엔진은 이를 문자열 일부나 위치 제어로 처리해 잘못 표시했다.
- **결정 실험:** 대상 엔진의 토큰 처리기와 실행 중 값을 원본과 대조했다. 고정값임이 확인된 항목만 문맥에 맞는 문구로 바꾸고, 위치 제어 코드는 글리프 배정에서 예약했다.
- **확정 결과:** 같은 숫자나 선행 패치에서 보인 글리프 모양은 대상 엔진에서 같은 의미를 보장하지 않았다.
- **전이 한계:** 토큰을 보존·치환하기 전에 대상 소비자의 의미와 실행 중 값 변화를 다시 확인한다.
- **관련 판단 기준:** `references/strategy/translation-workflow.md` §3.1·§4, `references/strategy/text-extraction.md` §4.4, `references/conventions/translation-artifacts.md` §3.

## MD-002

- **관측 범위:** Mega Drive의 화자 전환 대사와 PC-98 전투에서 인물 반응과 상태 서술이 분리된 문자열.
- **사고 맥락:** 문자열만 보고 번역하자 여러 화자의 대화가 독백으로 합쳐지거나, 인물이 말하는 반응이 객관적인 시스템 문구처럼 바뀌었다.
- **결정 실험:** 이벤트의 화자 제어, 실제 표시 창, 앞뒤 출력 순서를 원문과 함께 대조했다. 시리즈 번역은 해당 화자와 상황에 맞는지 확인한 뒤 표현 선택에만 참고했다.
- **확정 결론:** 화자·표시 역할은 문자열 자체가 아니라 실제 소비 경로가 결정했다.
- **전이 한계:** 비슷한 문구나 선행 번역만으로 역할을 정하지 않고, 영향 범위는 화자 제어와 표시 경로가 확인된 항목으로 한정한다.
- **관련 판단 기준:** `references/strategy/translation-workflow.md` §2.4.

## PCE-001

- **관측 범위:** PC Engine CD와 SNES의 배경 타일맵 인코더.
- **사고 맥락:** 논리 타일 번호를 물리 타일 좌표로 그대로 사용하거나 원본의 0이 아닌 기준값을 0으로 가정해 화면과 보호 영역을 손상했다.
- **결정 실험:** 원본 화면을 무수정 재인코딩하고 실제 업로드 목적지와 물리 타일을 대조했다. 원본이 쓰는 번호 변환을 적용하자 왕복 결과와 보호 영역이 함께 일치했다.
- **확정 결론:** 타일맵 번호의 기준과 물리 저장 좌표는 인코더의 편의값이 아니라 실제 소비 경로에서 구해야 했다.
- **전이 한계:** 화면·배경 계층마다 논리 번호에서 업로드 좌표로 이어지는 변환을 다시 구한다.
- **관련 판단 기준:** `references/platforms/pce.md` §2, `references/strategy/graphics-text.md` §2·§4.

## PCE-004

- **관측 범위:** PC Engine CD와 PlayStation의 시스템 글리프 공급 호출 뒤에 이어지는 비트맵 변환·VRAM 업로드 경로.
- **사고 맥락:** 한글 표시를 위해 전체 출력 루틴을 새로 만들어야 한다고 보았지만, 원본에는 글리프 공급 뒤의 변환·캐시·업로드 경로가 이미 있었다.
- **검증 근거:** 글리프 공급 지점만 호환 공급 함수로 바꾸고 원본의 뒤쪽 경로를 유지해 한글과 기존 문자가 함께 표시되는지 확인했다.
- **확정 결과:** 두 소비 경로에서는 글리프 공급 인터페이스만 대체해 원본의 변환·업로드를 재사용할 수 있었다.
- **전이 한계:** 다른 호출자는 공급 규약·비트 배열·버퍼 수명·캐시 식별값과 뒤쪽 변환을 다시 확인한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/reinsertion.md`, `references/strategy/runtime-assets.md`, `references/strategy/poc.md`.

## SATURN-003

- **관측 범위:** Saturn 마도물어의 CNX v2 압축 전투 자산.
- **사고 맥락:** 한국어 빌드에서 전투 애니메이션이 깨졌다. 파일 제외 실험은 원인 자산을 좁혔지만 번역 데이터 차이가 없고 자체 압축·해제 왕복도 통과해 다른 원인을 의심했다.
- **결정 실험:** 일본어판 원본의 해제 데이터를 고치지 않고 같은 압축기로 재압축한 ROM에서도 결함이 재현됐다. 자체 왕복은 계속 통과했으므로 압축기와 게임 해제기의 의미 차이를 조사했다.
- **확정 결과:** 압축기는 아직 출력되지 않은 0 초기화 구간까지 일치 후보로 허용했지만 게임 해제기는 이미 출력된 범위만 안전하게 역참조할 수 있었다. 참조 거리를 출력 완료 범위로 제한해 수정했다.
- **전이 한계:** 자체 왕복은 대상 해제기 호환성을 보장하지 않는다. 무수정 재압축물도 실제 소비자에서 검증한다.
- **관련 판단 기준:** `references/strategy/compression.md` §4, `references/strategy/debugging.md` §2.

## SATURN-004

- **관측 범위:** Saturn의 명령 인자, SNES의 압축 그래픽과 PC-98 문자열 안에서 포인터나 명령처럼 보인 raw byte.
- **사고 맥락:** 바이트 모양과 값 범위만으로 후보를 포함하자 명령 인자·압축 픽셀·문자 인코딩 일부가 참조로 잡혔다. 특정 접미 패턴을 일괄 제외하자 실제 참조도 빠졌다.
- **결정 실험:** 값이 저장된 레코드, 가리키는 주소의 범위·정렬, 실제 소비 형식을 함께 대조해 후보를 분류했다.
- **확정 결론:** 참조 여부는 바이트 모양이 아니라 저장 구조와 소비 경로가 결정했다.
- **전이 한계:** 문자열 내부 진입은 공유 뒷부분이나 내부 기준점일 수 있으므로 겹침만으로 버리지 않는다. 새 참조 형식은 저장 구조와 실제 읽기 경로를 다시 확인한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §1.2·§1.3·§3.5, `references/strategy/reinsertion.md` §2.

## SATURN-005

- **관측 범위:** Saturn 마도물어의 전투 메뉴 탭.
- **사고 맥락:** 메뉴를 열 때 VRAM 쓰기가 없고 주 폰트를 바꿔도 일본어 탭이 남아 표시 시점 생성과 주 폰트 표시 가설이 기각됐다.
- **결정 실험:** 해제한 스프라이트 자산에서 선택·비선택 상태의 라벨 쌍을 직접 디코드해 화면과 대응시켰다. 두 상태를 모두 교체한 빌드에서 전체 탭이 바뀌었다.
- **확정 결론:** 실제 수정 단위는 주 폰트가 아니라 미리 적재된 두 상태의 스프라이트 이미지였다.
- **전이 한계:** 표시 시점의 쓰기가 없다는 사실만으로 미리 적재된 파일이나 오프셋을 확정할 수는 없다. 저장 자산의 디코드와 표시 결과를 연결해야 한다.
