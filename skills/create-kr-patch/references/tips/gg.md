# Game Gear 국소 사례

## GG-001

- **관측 범위:** Game Gear 마도물어 1의 상점 가격 표시와 한글 표시 루틴.
- **사고 맥락:** 가격이 `금` 옆 대신 창 하단으로 밀리고 후속 대사 순서도 함께 흐트러졌다. 최종 VRAM 쓰기는 완성된 행을 복사할 뿐이어서 가격 커서가 직접 원인은 아니었다.
- **결정 실험:** 작업 버퍼 변경분에서 VRAM 전송까지 역추적하고 창별 타일 기준값을 원본 초기화 테이블과 대조했다. 공유 창과 일반 창을 같은 기준값으로 취급한 차이를 고치자 대사 순서와 문장 안 가격 표시가 함께 정상화됐다.
- **확정 결론:** 원인은 최종 가격 쓰기가 아니라 창을 그리기 전에 잘못 고른 기준값이었다.
- **전이 한계:** 다른 UI는 가격 슬롯과 창별 기준값 선택을 다시 확인한다.
- **관련 판단 기준:** `references/platforms/gg.md` §4, `references/strategy/debugging.md` §4.

## GG-005

- **관측 범위:** Game Gear 마도물어 1의 여러 포인터 테이블을 같은 여유 뱅크로 재배치한 텍스트 빌드.
- **선택 맥락:** 저장 공간을 아끼기 위해 한 문자열의 뒷부분을 다른 문자열과 공유할 수 있었다. 그러나 서로 다른 테이블까지 하나의 공유 목록으로 묶으면 한 테이블의 배치 변화가 다른 테이블의 문자열 참조를 깨뜨릴 수 있었다.
- **검증 근거:** 뱅크 공간 할당은 함께 쓰되 공유 후보 목록은 포인터 테이블마다 새로 만들었다. 같은 테이블 안의 공유만 유지한 빌드에서 각 소비 경로를 실행했다.
- **확정 결과:** 문자열 뒷부분은 같은 물리 뱅크 전체가 아니라 기준 주소·읽기 경로·수명이 같은 각 포인터 테이블 안에서만 공유할 수 있었다.
- **전이 한계:** 참조 표현·기준 주소·경로·적재 수명과 변경 단위가 같다고 입증된 테이블만 공유 범위를 넓힌다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §1.2·§2·§5.

## GG-006

- **관측 범위:** Game Gear 마도물어 2의 전체 번역 항목과 인물 초상 제어.
- **사고 맥락:** 번역 과정에서 인물 초상 선택 코드가 빠졌다. 전체 코드 수만 맞추면 같은 값도 다른 페이지나 가시 텍스트 뒤에 들어가 표정 전환 순서를 바꿀 수 있었다.
- **검증 근거:** 원문과 번역에서 페이지별 대기·출력 제어의 경계 순서가 같고, 원문의 초상 제어가 모두 각 페이지의 가시 텍스트 앞에 있음을 전수 확인했다. 각 페이지 접두부에 값·순서·중복·초기화를 복원하고, 제어코드를 뺀 대조 빌드에서 실제 처리기와 선택 상태 변화를 비교했다.
- **확정 결과:** 문자열 전체의 코드 개수가 아니라 각 페이지 앞에 놓인 제어코드의 값과 순서를 맞춰야 원본의 인물 전환이 복원됐다.
- **전이 한계:** 원문과 번역의 페이지 경계가 같고 제어가 페이지 접두부에만 있다는 전수 근거가 있을 때만 성립한다. 중간 제어나 페이지 구조 변경이 있으면 대응을 추정하지 않는다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §3.1·§3.3, `references/strategy/translation-workflow.md` §4, `references/conventions/translation-artifacts.md` §3.

## GG-007

- **관측 범위:** Game Gear 마도물어 1의 일본어 원문과 영문 기반 엔진, NES 파로디우스다! 일본어판과 선행 영어 패치의 토큰 의미 차이.
- **사고 맥락:** Game Gear에서는 특정 변수 토큰이 대상 엔진에서도 같은 의미라고 보고 보존했지만, 대상 엔진은 이를 영문 문자열의 일부로 표시했다. NES에서는 선행 영어 패치의 문장부호 글리프 코드를 일본어판 소비자가 탁점·반탁점 위치 제어로 처리해 한글 타일이 흩어졌다.
- **결정 실험:** 각 대상의 토큰 처리기와 포인터·글리프 매핑을 원본과 대조했다. Game Gear의 정적 상태 토큰은 문맥에 맞는 한글 고정 문구로 바꾸고, NES의 위치 제어 코드는 글리프 배정에서 예약했다.
- **확정 결과:** 같은 숫자·토큰 표기나 선행 패치의 글리프 모양은 대상 엔진에서 같은 의미를 보장하지 않았다.
- **전이 한계:** 고정 문구 치환은 값이 실행 중 상태에 따라 달라지지 않는다고 확인된 범위에만 적용한다. 다른 토큰은 대상 엔진의 처리와 실행 중 값 변화를 다시 확인한다.
- **관련 판단 기준:** `references/strategy/translation-workflow.md` §3.1·§4, `references/strategy/text-extraction.md` §4.4, `references/conventions/translation-artifacts.md` §3.

## GG-008

- **관측 범위:** Game Gear 마도물어 A의 문자열 표와 필드 화면의 동적 금액·상태 문자열.
- **사고 맥락:** 길이 0인 항목을 빈 문자열로 보고 포인터를 0으로 바꾸자 게임이 부트 코드를 문자열로 읽었다.
- **결정 실험:** 원본 표를 전수 대조하자 문제 항목만 파일 뱅크 밖 WRAM의 실행 중 조립 문자열을 가리켰다. 원본 포인터를 보존하자 정상화됐다.
- **확정 결과:** 이 범위의 길이 0은 널이나 빈 데이터가 아니라 외부에서 생성되는 문자열의 참조였다.
- **전이 한계:** 빈 항목은 널, 빈 문자열, 별도 영역 참조, 실행 중 만들어지는 문자열 참조 가운데 무엇인지 확인한 뒤 보존 방식을 정한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §1.2·§2·§6, `references/strategy/runtime-assets.md` §2, `references/conventions/data-formats.md` §4.

## GG-009

- **관측 범위:** Game Gear 마도물어 A의 두 텍스트 루프가 공유하는 글리프 확장 루틴 훅.
- **사고 맥락:** 접두 인덱스를 계산하려고 `B`를 임시로 쓴 훅은 한 루프에서는 동작했지만, 다른 루프에서는 `B`가 줄당 문자 카운터였다. 복귀 뒤 카운터가 작은 접두 인덱스 값으로 바뀌어 반복 횟수가 0을 지나 큰 값으로 되돌아가고 화면 전송까지 진행하지 못했다.
- **결정 실험:** 공유 루틴의 호출자를 전수 대조해 진입·복귀 레지스터 의미를 분리했다. `B`를 보존하고 각 호출자의 그래픽 플레인 상태를 명시적으로 정규화한 뒤 대사·필드 텍스트 경로에서 글리프 전개와 화면 전송을 확인했다.
- **확정 결과:** 두 번째 호출자에서 `B`는 줄당 문자 카운터였고 그래픽 평면 상태도 호출자마다 달랐다. `B`와 각 경로의 평면 상태를 보존한 뒤에야 공유 훅이 두 표시 경로에서 동작했다.
- **전이 한계:** 공유 훅은 확인한 모든 호출자의 입력·출력과 원래 동작을 설명할 수 있는 범위에서만 채택한다. 보존할 레지스터는 경로마다 다시 판정한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §4, `references/strategy/debugging.md` §3·§5.

## GG-010

- **관측 범위:** Game Gear 마도물어 2에서 실측한 7×3 대사창과 창 태그 없이 사용된 페이지 전환 제어.
- **사고 맥락:** 스크립트 구간만 보고 넓은 창을 가정하면 같은 구간 안의 좁은 대사창을 놓쳤다. 실제로 넓은 구간에 속한 13타일 한 줄이 좁은 창 태그로 소비되어 화면을 넘었고, 한 줄 폭만 세는 검사는 다음 행으로 재배치할 수 있는 페이지까지 모두 같은 위반으로 묶었다.
- **검증 근거:** 원문 페이지와 실제 7타일 열을 대조하고 좁은 창의 넘침을 재현해 구간 기반 가설을 기각했다. 각 페이지의 현재 행 수, 어절 재줄바꿈 행 수와 공백 제외 음절 최소 행 수를 비교해 문장 조정과 재배치 후보를 갈랐다. 해당 제어가 현재 창을 비우고 다음 페이지를 열며 첫 글자를 자르지 않음도 연속 플레이로 확인했다.
- **확정 결과:** 실제 창 크기는 스크립트 구간이 아니라 현재 창 태그가 정했다. 폭과 행을 함께 계산하고, 한 페이지에 들지 않는 내용은 확인된 페이지 전환 제어로 나눌 수 있었다.
- **전이 한계:** 페이지를 늘릴 때는 해당 제어가 초상·창·입력·이벤트 상태를 보존하는지 경로별로 확인한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §4.4, `references/strategy/translation-workflow.md` §4, `references/strategy/build-and-verify.md` §5, `references/strategy/reinsertion.md` §6.

## GG-011

- **관측 범위:** Game Gear 마도물어 1의 한글 하단 정렬 뒤 전투 치명타 메시지와 직전 주문명이 공유한 창 영역.
- **사고 맥락:** 한글 정렬로 표준 메시지의 행이 이동하자 치명타 메시지를 그리는 한 호출자만 창을 지우지 않아 직전 주문명의 일부가 남았다. 대화 전체를 초기화하거나 공용 지우기 루틴을 바꾸는 방식은 실제로 지우기가 빠진 호출자와 맞지 않았다.
- **결정 실험:** 결함 순간에 이전 타일이 남은 상태를 확인하고, 표준 메시지는 지우기 뒤 그려져 잔여가 없음을 대조했다. 지우기 없는 경로의 호출자를 열거해 문제 호출자만 기존 지우기 포함 경로로 보냈다.
- **확정 결과:** 잔여 타일의 원인은 전역 지우기 부족이 아니라 호출자별 지우기 책임 차이였다.
- **전이 한계:** 경로를 바꾸기 전 호출자별 선행 지우기·좌표·정렬·소비 의미를 확인하고 정상 호출자도 함께 회귀 검증한다.
- **관련 판단 기준:** `references/strategy/debugging.md` §3·§5, `references/strategy/reinsertion.md` §4·§6, `references/strategy/runtime-assets.md` §2.
