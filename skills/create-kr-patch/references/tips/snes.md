# SNES 국소 사례

## SNES-001

- **관측 범위:** SNES 마도물어의 2바이트 접두사 인코딩.
- **사고 맥락:** 고정 슬롯에 맞춰 번역문을 원본 바이트 길이에서 자르자 끝에 `FB`·`FA` 접두사만 남았다. 게임은 바로 뒤의 `FF` 종료자를 두 번째 문자 바이트로 소비해 종료를 잃었다.
- **결정 실험:** 절단 결과를 같은 토큰 분석기로 다시 읽고 끝 토큰이 완결된 문자·제어코드인지 검사했다. 불완전한 접두사를 제거해 직전 문자 경계로 되돌리자 오류가 사라졌다.
- **확정 결론:** 정해진 바이트 수에 맞춘 절단은 길이 비교가 아니라 게임의 토큰 경계에서 끝나야 했다.
- **전이 한계:** 짝수 바이트 절단만으로 모든 가변 길이 인코딩의 경계가 보장되지는 않는다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §1.1, `references/strategy/text-extraction.md` §2.

## SNES-002

- **관측 범위:** SNES 나조뿌요 1(룰루의 루)에서 항상 2바이트씩 읽는 텍스트 경로.
- **사고 맥락:** 초기 한글 인코더가 일본어처럼 1바이트 공백·제어코드를 냈고, 그 뒤의 타일쌍이 홀수 경계에서 시작해 화면이 깨졌다.
- **결정 실험:** 텍스트 소비자가 항상 2바이트를 읽고 읽기 위치를 2바이트씩 전진함을 확인했다. 모든 토큰을 워드 단위로 직렬화하고 홀수 위치의 제어코드를 금지하자 정렬 문제가 사라졌다.
- **확정 결론:** 토큰 폭은 문자의 표시 형식이 아니라 실제 소비자의 읽기 단위에 맞춰야 했다.
- **전이 한계:** 65816을 쓴다는 사실만으로 텍스트 읽기 폭이 2바이트라고 결론내리지 않는다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §2.

## SNES-003

- **관측 범위:** SNES 마도물어의 16×16 글리프와 타일맵 작성기.
- **사고 맥락:** 한글 타일은 의도한 WRAM 위치에 올라갔는데 여러 배치 가설을 바꿔도 화면은 계속 다른 타일을 읽었다.
- **결정 실험:** 타일맵 작성기의 인덱스 계산 경로를 따라가 가로 인덱스가 문자 코드 N을 `N×2`, `N×2+1`로 변환함을 확인했다. 실제 한 글자는 그 좌우 쌍을 위아래로 둔 2×2 타일이었고 데이터 주소만 맞춘 실험은 이 변환을 놓치고 있었다.
- **확정 결론:** 이 경로에서는 글리프 주소뿐 아니라 `N→N×2, N×2+1` 변환과 2×2 타일 배치를 함께 맞춰야 했다.
- **전이 한계:** 다른 표시 루틴은 코드→타일 변환을 다시 추적한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/runtime-assets.md` §2.

## SNES-004

- **관측 범위:** SNES 나조뿌요 2에서 NMI 때 조건 문구 타일을 덮어쓰는 퍼즐 화면의 CHR·타일맵.
- **사고 맥락:** 퍼즐 처리와 NMI 사이에 새 상태를 전달해 조건 문구 타일을 덮는 구조는 화면 진입·재진입과 인접 화면을 안정적으로 구분하지 못했다.
- **결정 실험:** 새 신호 의존을 제거하고 NMI 소비 시점의 화면 모드, BG1 타일맵 기준점과 원본 타일맵 패턴을 함께 검사했다. 단일 전역 상태만 맞는 다른 화면을 반례로 제외한 뒤 대상 화면에서만 덮어쓰기가 실행됐다.
- **확정 결론:** NMI가 이미 읽던 화면 모드·타일맵 기준점·원본 타일맵 패턴만으로 대상 화면을 안정적으로 구분할 수 있었다.
- **전이 한계:** 다른 화면에서는 소비 시점의 화면 모드·타일맵 기준점·원본 타일맵 패턴 조합이 실제로 대상을 구분하는지 다시 확인한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §4, `references/strategy/debugging.md` §2.

## SNES-009

- **관측 범위:** SNES 나조뿌요 1(룰루의 루)의 분기별 텍스트 경로.
- **사고 맥락:** 한 스토리 분기만 시작 직후 화면이 깨졌다. 빌드가 테이블 끝의 특수 포인터를 포인터 목록에서 빠뜨리고 첫 텍스트 주소도 한 바이트 앞에서 시작해 그 포인터를 덮었다.
- **결정 실험:** 해당 분기의 실제 로드가 테이블 끝 특수 포인터를 읽는 경로임을 역어셈블하고 원본 상수·포인터 수·첫 텍스트 주소를 함께 대조했다.
- **확정 결론:** 테이블 끝 특수 포인터 누락과 첫 텍스트 주소의 1바이트 오차가 해당 분기의 포인터를 덮은 원인이었다. 포인터 목록을 원본 고정 테이블과 실제 읽기 경로에서 다시 확정해 복구했다.
- **전이 한계:** 스토리 분기 수와 소비 경로 수가 같다고 가정하지 않는다.
- **관련 판단 기준:** `references/strategy/build-and-verify.md` §4.

## SNES-010

- **관측 범위:** SNES 나조뿌요 2의 멀티바이트 제어코드.
- **사고 맥락:** 스캐너와 인코더가 단일 `FF`를 종료자로 취급해 일부 항목을 잘못 추출했다. 게임은 그 바이트를 종료가 아니라 글자 `今`으로 그렸다.
- **결정 실험:** 원본 소비자를 따라 `00 00`은 종료, `00 FF`는 버튼 대기, 단일 `FF`는 문자임을 분리했다. 전체 항목을 다시 읽어 원본 종료 형태와 대조하고 오염된 범위를 재추출했다.
- **확정 결론:** 이 경로에서 `00 00`은 종료, `00 FF`는 버튼 대기, 단일 `FF`는 문자였다. 첫 바이트만 본 종료 판정이 오추출 원인이었다.
- **전이 한계:** 다른 파서는 종료 시퀀스와 상태를 다시 추적한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §2.

## SNES-011

- **관측 범위:** SNES 마도물어: 하나마루 대유치원아의 여러 LZ 압축 UI.
- **선택 맥락:** UI의 압축 블록을 직접 재패킹하는 대신, 게임이 이미 호출하는 해제 경계와 후속 DMA를 유지하면서 일부 CHR·타일맵만 바꿀 경로가 필요했다.
- **검증 근거:** 실제 해제 호출마다 입력 식별값, 출력 WRAM과 후속 DMA 목적지를 연결했다. 전체 블록은 빌드 시 해제·수정한 비압축 결과로 대체하고, 부분 변경은 원본 해제 뒤 WRAM에 필요한 부분을 덮어쓴 다음 기존 DMA가 그대로 소비하게 했다. 서로 다른 화면의 진입·재진입에서 결과를 확인했다.
- **확정 결과:** 게임의 기존 해제 직후에 필요한 부분만 바꾸고 후속 DMA를 그대로 사용해, 새 압축기나 별도 전송 경로 없이 압축 UI를 교체할 수 있었다.
- **전이 한계:** 개입할 해제 호출은 입력 식별값·출력 상한·호출 상태·후속 소비자와 마지막 쓰기가 모두 연결된 범위로 제한한다.
- **관련 판단 기준:** `references/strategy/compression.md` §5, `references/strategy/runtime-assets.md` §2, `references/strategy/reinsertion.md` §4.

## SNES-012

- **관측 범위:** SNES 마도물어: 하나마루 대유치원아의 장비·상점 OBJ 글자 타일.
- **사고 맥락:** 원본 OBJ CHR은 화면 초기화 때 WRAM에서 VRAM으로 한 번만 전송됐다. 그 뒤 매 프레임 갱신되는 WRAM을 고쳐도 화면은 바뀌지 않았고, 넓은 훅은 필드 NPC 타일까지 덮었다.
- **검증 근거:** 대상 OBJ VRAM의 적재 순서와 마지막 쓰기 경로를 추적하고 화면 출력 중지 구간에서 ROM→OBJ VRAM 타일 DMA를 수행했다. 상점은 해제기가 상태 레지스터를 덮기 전에 입력 상태를 판정하고 마지막 관련 LZ 호출 뒤에만 전송하도록 좁혀 NPC 충돌을 제거했다.
- **확정 결과:** 원본 OAM 배치·속성을 유지해야 하는 미리 적재된 글자는 마지막 관련 적재 뒤 픽셀 타일만 OBJ VRAM에 직접 덮어야 했다.
- **전이 한계:** OBJ 타일 전송과 OAM 배치는 분리해 검증한다. 다른 화면에서는 화면 출력이 멈춘 시점인지, DMA 설정이 복원되는지, 목적지·팔레트·마지막 쓰기와 발동 조건이 맞는지 다시 확인한다.
- **관련 판단 기준:** `references/strategy/runtime-assets.md` §2, `references/strategy/graphics-text.md` §3, `references/strategy/reinsertion.md` §4.

## SNES-013

- **관측 범위:** SNES 마도물어의 월드맵 제목과 SNES 나조뿌요 2의 에디터 테두리 로고.
- **선택 맥락:** 두 자산 모두 한 라벨의 글자·배경·윤곽이 여러 물리 타일에 걸쳤고, 나조뿌요 2 로고는 세로 그라데이션과 상단 광택도 라벨 전체에서 이어졌다. 타일별로 따로 그리면 경계의 윤곽·그라데이션·광택이 끊겼다.
- **검증 근거:** 각 자산의 타일·서브타일 순서와 팔레트를 확정한 뒤 글자·배경·외곽선·그라데이션·광택을 라벨 전체 그림에 먼저 합성했다. 완성 픽셀을 실제 저장·전송 순서로 나누고 여러 진입 화면에서 타일 경계와 효과의 연속성을 확인했다.
- **확정 결과:** 라벨 전체 그림을 완성한 뒤 저장·전송 순서에 맞춰 타일로 나누자 두 자산의 경계와 시각 효과가 이어졌다.
- **전이 한계:** 다른 자산은 전체 그림의 좌표·보호 영역·저장 순서를 다시 확인한 뒤 분할한다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §2·§3·§4, `references/strategy/runtime-assets.md` §2, `references/strategy/build-and-verify.md` §5.

## SNES-014

- **관측 범위:** SNES 마도물어의 3바이트 뱅크 간 참조와 2바이트 같은 뱅크 전용 참조가 섞인 텍스트 재배치.
- **선택 맥락:** 같은 뱅크에 남아야 하는 문자열과 다른 뱅크로 이동할 수 있는 문자열이 제한된 내부 공간을 함께 요구했다. 제약이 강한 항목을 기존 여유 공간에 바로 배치하면 전체 수요를 수용하지 못했다.
- **검증 근거:** 확인된 참조 목록으로 이동 가능성을 먼저 분류했다. 기존 영역을 넘는 데이터 중 뱅크 간 참조가 가능한 항목을 외부로 옮겨 원래 영역을 회수한 뒤, 같은 뱅크 전용 참조 대상을 그 공간에 배치하고 모든 포인터와 원본 영역 소거를 검증했다.
- **확정 결과:** 혼합 참조의 할당 순서는 공간 제약뿐 아니라 먼저 옮긴 데이터가 비운 원래 영역을 다음 항목이 쓸 수 있는지도 반영해야 했다.
- **전이 한계:** 모든 참조와 각 포인터가 나타낼 수 있는 주소 범위를 확인하고, 회수할 원본 영역에 중간 진입·내부 포인터·다른 소비자가 없을 때만 성립한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §2·§3·§5, `references/conventions/data-formats.md` §4.

## SNES-016

- **관측 범위:** SNES 뿌요뿌요 2의 스토리 대사 폰트 LZ 압축 원본 위치 조사.
- **사고 맥락:** WRAM·VRAM 중단점은 누적 글리프 캐시와 DMA 때문에 적재 순간을 반복해서 놓쳤지만 실행 중 올라온 일본어 글리프 바이트와 검증한 LZ 해제기는 확보돼 있었다.
- **검증 근거:** ROM의 각 후보 위치에서 검증한 압축 형식으로 해제를 시도하고 출력에 실행 중 글리프 타일이 모두 포함되는 위치를 역검색했다. 후보 결과를 그려 본 뒤 다른 글리프 표본도 WRAM과 바이트 단위로 대조했다.
- **확정 결과:** 실행 중 글리프를 비교 기준으로 ROM 전체의 후보를 해제해 검색한 결과 실제 압축 원본 위치와 내부 글리프 배치를 찾았다.
- **전이 한계:** 압축 원본 후보는 검증한 압축 형식·출력 상한 아래에서 여러 실행 중 표본과 최종 표시까지 맞을 때 확정한다.
- **관련 판단 기준:** `references/strategy/compression.md` §2·§3, `references/strategy/initial-survey.md` §2, `references/strategy/runtime-assets.md` §2.

## SNES-017

- **관측 범위:** SNES 마도물어의 대사 행 종료와 NES 파로디우스다! 엔딩의 텍스트 표시·지우기 범위.
- **사고 맥락:** SNES에서는 빈 글리프 패딩을 제거하자 짧아진 행 뒤에 이전 타일이 남았다. NES에서는 화면에 보이는 여유 행까지 문장을 늘리자 게임이 지우지 않는 배경을 덮어 다음 문장에도 손상이 남았다.
- **검증 근거:** SNES에서는 행 종료 경로가 남은 타일을 지우도록 책임을 옮긴 뒤 패딩을 제거했다. NES에서는 문장을 게임이 실제로 지우는 행 안으로 제한하고 게임의 원래 화면 전환 뒤 배경 보존을 확인했다.
- **확정 결과:** 두 사례 모두 화면에 보이는 여유가 아니라 게임이 실제로 쓰고 다음 화면으로 넘어갈 때 지우는 범위가 레이아웃 한계였다.
- **전이 한계:** 패딩 제거·행 확장은 종료 토큰, 쓰기·지우기 범위와 다음 상태 전환을 함께 확인한 화면에서만 적용한다.

## SNES-021

- **관측 범위:** SNES 마도물어의 전투 대사창과 한국어 대사의 가시 폭·행 수에 따른 창 크기 계산.
- **사고 맥락:** 일본어 대사에 맞춘 고정 폭·높이를 그대로 쓰면 더 길거나 여러 행인 한국어가 창을 넘었고, 반대로 바이트 수나 토큰 수를 곧바로 화면 폭으로 쓰면 제어 토큰과 행 전환까지 가시 글리프로 셌다. 화면 오른쪽에 가까운 대사창은 내용에 맞춘 폭만으로는 실제 화면 경계를 넘을 수 있었다.
- **검증 근거:** 한국어 대사를 소비자와 같은 토큰 경계로 읽어 제어 토큰은 폭에서 제외하고 행 전환을 반영한 최대 가시 폭과 행 수를 계산했다. 그 결과로 창의 폭·높이를 정하되 오른쪽 끝은 실제 화면 경계에서 별도로 제한했고, 계산된 창과 대사 표시를 실제 전투 화면에서 확인했다.
- **확정 결과:** 이 경로의 창 크기는 일본어 고정값이나 직렬화 길이가 아니라 한국어 토큰열의 최대 가시 폭·행 수가 결정했고, 화면 경계는 내용 크기와 별도로 적용되는 배치 제한이었다.
- **전이 한계:** 다른 창은 소비자의 토큰 의미·좌표계와 실제 표시 경계를 다시 측정한다.
- **관련 판단 기준:** `references/strategy/translation-workflow.md` §4, `references/strategy/reinsertion.md` §6, `references/strategy/build-and-verify.md` §4·§5.

## SNES-022

- **관측 범위:** SNES 마도물어의 선택지 선택 강조와 원문보다 길어진 한국어 선택 행.
- **사고 맥락:** 선택 행의 한국어가 길어졌지만 선택 강조는 원문 길이에 해당하는 앞부분만 덮어, 커서가 선택 상태를 바꿔도 행 뒤쪽은 비선택 상태처럼 남았다. 전체 행을 덮는 강조용 타일 데이터가 있어도 이를 읽는 범위를 함께 늘리지 않으면 가시 결과는 달라지지 않았다.
- **검증 근거:** 강조용 타일 데이터만 늘려서는 행 뒤쪽이 바뀌지 않았고, 정적 분석에서 이를 읽는 범위도 원문 길이에 묶여 있음을 확인했다. 두 범위를 한국어 행 전체로 맞춘 결과까지는 정적으로 확인했으나, 선택·비선택 전환의 실제 표시는 증거 범위에 포함되지 않았다.
- **확정 결과:** 선택 강조 자산과 이를 읽는 범위를 함께 늘려야 한다는 정적 조건이 확인됐다.
- **전이 한계:** 강조 데이터와 읽기 범위를 맞춘 정적 조건만으로 완료 처리하지 않는다. 실제 선택·비선택 전환에서 각 행 끝까지 상태가 바뀌는 런타임 증거를 확인한다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §1·§3·§4, `references/strategy/runtime-assets.md` §2, `references/strategy/reinsertion.md` §6, `references/strategy/build-and-verify.md` §4·§5.
