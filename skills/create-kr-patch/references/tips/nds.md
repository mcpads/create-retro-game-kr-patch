# Nintendo DS 국소 사례

## NDS-001

- **관측 범위:** Nintendo DS판 드래곤 퀘스트 IX 일본어판 리비전 0의 이름 입력 후보와 선택 후 재표시 경로.
- **사고 맥락:** 이름 입력 화면에서 사용하는 폰트로 보이는 NFTR의 `い` 글리프를 바꿨지만 화면은 변하지 않았다. 하나의 입력 화면이므로 후보 문자표와 선택 후 재표시가 같은 폰트 자산을 쓴다고 보기 쉬웠다.
- **검증 근거:** 후보 문자표의 BNCG만 바꾼 빌드에서는 후보만 한글로 보이고 입력 필드는 일본어 글리프를 유지했다. BNCG와 같은 코드 슬롯의 MES 글리프를 함께 바꾼 빌드에서는 후보와 입력 필드·상단 이름이 같은 한글로 표시됐고, 확인 화면·첫 전투 UI·필드 이름 태그·메인 메뉴에서도 재사용됐다.
- **확정 결과:** 이 이름 입력 경로에서 후보 문자표는 미리 그려 넣은 BNCG 그래픽, 선택 후 이름 재표시는 MES 글리프가 공급했다. 입력 후보와 결과 표시를 일관되게 만들려면 같은 문자 슬롯에 대응하는 두 소비 경로를 함께 바꿔야 했다.
- **전이 한계:** 다른 화면은 후보 표시와 결과 표시의 공급 경로를 각각 추적한다. 한 경로에서 반응하지 않은 NFTR을 다른 화면에서 배제하지 않는다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §5, `references/strategy/runtime-assets.md` §2.

## NDS-002

- **관측 범위:** Nintendo DS판 드래곤 퀘스트 IX 일본어판 리비전 0의 GP2 컨테이너 초기화와 내부 MES 폰트 항목 추가 빌드.
- **사고 맥락:** 한글 글리프를 대량 추가한 ROM이 타이틀 전에 흰 화면에 머물렀다. 초기 빌드에서는 코드 테이블 정렬, GP2 내부 파일 크기와 항목 수가 함께 변해 어느 차이가 실패를 만들었는지 분리되지 않았다.
- **검증 근거:** 코드 순서를 바로잡고 MES 파일별 확장을 분리했다. 서로 한 항목 차이인 빌드를 비교하자 후보표를 바꾸지 않아도 초기화 결과가 갈렸다. 컨테이너 내부 파일 크기는 유지하되 헤더와 데이터의 항목 구조를 정상 부팅한 대조군과 같게 만든 빌드는 다시 타이틀에 도달했다.
- **확정 결과:** 파일 크기를 같게 둔 대조 빌드에서도 실패가 내부 항목 구조를 따라 이동했다. 이 빌드 집합에서는 컨테이너의 물리적 증가만으로 부팅 실패를 설명할 수 없었다.
- **전이 한계:** 자산 확장 뒤 초기화가 깨지면 관측한 항목 수를 상한으로 고정하지 않는다. 물리적 크기와 항목 수·메타데이터·데이터 배치를 분리한 대조 빌드로 실패가 따라가는 경계를 좁히고, 초기화 통과와 추가 자산의 실제 소비는 따로 판정한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §3.2, `references/strategy/debugging.md` §2·§3.

## NDS-003

- **관측 범위:** Nintendo DS판 러브플러스의 LC10·LC12 NFTR 원본과 한글 글리프를 추가한 파일.
- **사고 맥락:** 문서에 쓰인 청크명을 그대로 원본 바이트에서 찾거나, 새 문자 매핑을 기존 CMAP 연결 목록 끝에 붙여도 소비자가 찾아줄 것으로 보기 쉬웠다.
- **검증 근거:** 두 원본과 두 확장 파일을 해석한 뒤 바이트 단위로 동일하게 재직렬화했다. 파일에는 `NFTR`·`FINF`·`CGLP`·`CWDH`·`CMAP`이 각각 `RTFN`·`FNIF`·`PLGC`·`HDWC`·`PAMC` 순서로 저장돼 있었고, 두 원본의 CMAP 연결 목록 끝에는 `0x0000..0xFFFF` 범위의 매핑이 있었다. 한글 매핑을 그 앞에 연결한 빌드는 부팅과 기존 일본어 메뉴 표시를 유지했다.
- **확정 결과:** 이 네 파일에서는 태그의 역순 저장과 연결 포인터를 반영해야 원본을 바이트 동일하게 재직렬화할 수 있었다. 새 매핑을 앞에 둔 파일도 적재와 기존 글리프 표시는 유지했지만, 실제 소비자가 CMAP을 어떤 순서로 조회하는지와 새 한글 글리프를 소비하는지는 확인되지 않았다.
- **전이 한계:** 태그의 저장 바이트 순서는 대상 파일에서 다시 확인한다. 매핑 순서는 실제 소비자의 조회 규칙과 새 글리프 표시가 확인되기 전에는 재삽입 규칙으로 일반화하지 않는다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §2, `references/conventions/project-conventions.md` §5.1.
