# PlayStation 국소 사례

## PS1-001

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 부트 재적재 뒤 RAM 훅과 R3000A I-cache 상태.
- **사고 맥락:** 네 명령 trampoline이 16바이트 cache line 두 개에 걸친 상태에서 부트 해제기가 같은 RAM을 다시 썼다. RAM에는 패치가 있었지만 line별 stale/fresh 상태가 달라 원본 `jal`과 패치된 delay slot이 섞여 실행되고 보존 register가 오염됐다.
- **검증 근거:** 두 line의 RAM·실행 명령 조합과 register 결과를 대조해 혼합 실행 사슬을 확인했다. trampoline을 한 cache line 안의 세 명령으로 줄이고 다음 원본 명령을 delay slot으로 유지했으며, 훅 본체는 uncached KSEG1 alias에서 실행하도록 바꿨다.
- **확정 결과:** 다시 쓰이는 patch site의 실행 단위를 한 cache line 안에 묶고 uncached 경로를 사용해 stale/fresh 명령 혼합을 제거했다.
- **전이 한계:** 다른 훅은 재적재 범위·cache line·alias와 실행 순서를 확인해 invalidation·uncached 경로를 선택한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §4·§6, `references/strategy/runtime-assets.md` §2, `references/strategy/debugging.md` §3.

## PS1-002

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 Story SEQ에서 한 포인터가 다른 메시지 내부의 완전한 제어 세그먼트 경계로 진입하고, 추출 단계가 겹친 문자열을 합친 경우.
- **사고 맥락:** 중복 제거 뒤 남은 엔트리를 목록 순서로 다시 번호 매기면 다른 포인터 슬롯을 번역하게 된다. 제거된 내부 포인터를 별도 원문 블록으로 복사하면 부모 메시지는 번역돼도 그 포인터로 진입한 화면에는 원문 tail이 남았다.
- **검증 근거:** 추출 산출물이 원본 포인터 슬롯 번호를 유지하고 재삽입기가 이를 우선해 읽는 회귀 테스트를 만들었다. 별도 내부 포인터는 원문 부모 안의 완전한 제어 세그먼트 경계와 번역된 부모의 같은 세그먼트 경계를 대응시켜 파생했으며, 중첩된 각 포인터가 기대한 번역 tail을 소비하는 합성 SEQ 테스트로 확인했다.
- **확정 결과:** 문자열을 합쳐도 재삽입 정체성은 원본 포인터 슬롯에 귀속하고, 부모 내부 타깃은 목록 순서나 원문 바이트 거리가 아니라 번역 뒤에도 보존되는 완전한 구조 anchor로 다시 계산해야 했다.
- **전이 한계:** 이 방식은 원문과 번역의 구조 anchor가 가역적으로 대응할 때만 성립한다. 대응하지 않는 내부 진입은 추정하지 않는다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §1.3·§4.1·§4.2, `references/strategy/reinsertion.md` §1.2·§2·§3.

## PS1-003

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전 `CSMES.BTX`의 소형 데이터 로드 확인창 라벨과 실제 선택 배경 팔레트.
- **선택 맥락:** 제한된 팔레트의 작은 라벨에서 배경·외곽선·본문의 역할을 분리해야 했다. 이 자산은 세 역할에 해당하는 팔레트 인덱스만 쓰는 픽셀 크리스프 방식으로 조판했다.
- **검증 근거:** 산출물이 선언한 세 인덱스 밖의 색을 쓰지 않는지 검사하고, 실제 데이터 로드 확인창에서 `예`·`아니오`를 표시했다. 선택 배경 위에서도 외곽선과 본문이 분리되어 판독됐고, 글자 경계 상자 잘림과 인접 UI 손상이 없음을 확인했다.
- **확정 결과:** 세 팔레트 역할로 제한한 픽셀 크리스프 조판이 이 확인창의 실제 선택 배경에서 대비·판독성과 경계 보존을 함께 통과했다.
- **전이 한계:** 다른 UI는 실제 팔레트와 상태 배경에서 대비·잘림을 다시 확인한다. 안티앨리어싱과의 우열은 검증하지 않았다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §2·§4, `references/strategy/font-strategy.md` §4, `references/strategy/build-and-verify.md` §5.

## PS1-004

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 그래픽 카탈로그 관측 스냅샷에서 bpp·폭·높이와 화면 역할이 분류된 BTX 16개. 이 가운데 실제 화면 검증은 별도 상태로 관리됐다.
- **사고 맥락:** BTX에는 4bpp와 8bpp 자산이 함께 있고 텍스트가 아이콘·숫자·배경과 같은 아틀라스에 섞여 있었다. 같은 파일 길이를 만족하는 폭·높이·bpp 조합이 여러 개라 크기만으로 하나를 고르면 일부 글자나 아이콘만 우연히 보이는 잘못된 저장 해석을 채택할 수 있었다.
- **검증 근거:** 해제된 정확한 길이를 만족하는 `bpp × 폭 × 높이` 후보를 먼저 열거하고, 각 후보의 전체 이미지 연속성, 행 반복과 블록 구조, 팔레트 인덱스 분포를 대조했다. 텍스트·아이콘·배경이 함께 일관된 이미지가 되고 기록된 화면 역할과 모순되지 않는 조합만 분류 자산의 저장 해석으로 채택했다. 실제 화면에서 확인된 자산은 그 결과를 별도 런타임 근거로 연결했다.
- **확정 결과:** 이 BTX 부분집합에서는 정확한 길이 호환성이 저장 해석 후보의 필요조건일 뿐 충분조건이 아니었다. bpp·폭·높이 조합이 전체 이미지 구조와 팔레트를 함께 설명할 때만 확정할 수 있었다.
- **전이 한계:** 분류 밖 자산은 bpp·치수와 소비 경로를 따로 판정한다. 파일명·크기·선행판 대응만으로는 부족하다.
- **관련 판단 기준:** `references/strategy/graphics-text.md` §1·§2·§3, `references/strategy/initial-survey.md` §2, `references/strategy/runtime-assets.md` §2.

## PS1-005

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 BIOS `Krom2RawAdd` 글리프 공급 경계와 첫 한글 폰트 CD 적재 경로.
- **사고 맥락:** BIOS 조회만 대체하고 기존 텍스트 파서·1bpp→4bpp 변환·VRAM 업로드·글리프 캐시를 유지하면 폰트 경로 전체가 해결된다고 보기 쉬웠다. 한글 글리프는 표시됐지만 첫 사용 시 디스크에서 폰트를 읽는 동안 음악이 중단됐다.
- **검증 근거:** 한글 범위에는 호환 30바이트 글리프를 반환하고 나머지는 원래 BIOS로 보내, 한글 표시와 일본어 폴백 및 후단 변환·업로드 재사용을 확인했다. CD 명령 완료와 모드 복원 순서를 보완한 뒤에도 첫 폰트 적재 때 음악 중단은 남았다.
- **확정 결과:** 글리프 공급 ABI 대체와 기존 후단 소비 경로 재사용은 성립했지만, 새 자산의 첫 CD 적재가 공유 장치·오디오 상태를 보존한다는 배포 조건은 통과하지 못했다.
- **전이 한계:** 후단 재사용은 공급 ABI·자산 수명·캐시 식별값이 연결될 때만 성립한다. 첫 적재의 CD·오디오 상태 보존은 별도 게이트다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/reinsertion.md`, `references/strategy/runtime-assets.md`, `references/strategy/build-and-verify.md`.

## PS1-006

- **관측 범위:** PlayStation 와쿠와쿠 뿌요뿌요 던전의 MENU·SCENE·SAVE 등 고정 길이 2바이트 문자열 소비 경로.
- **사고 맥락:** 짧아진 번역의 남는 바이트를 `0x0000`으로 채우고 마지막 종료자 하나만 보존했다. 소비자는 `0x0000`을 빈 공간이 아니라 오류 글리프 코드로 해석했고, 제어 접미부나 2바이트 토큰 중간을 자르는 경로도 남아 있었다.
- **검증 근거:** 오류 표시가 난 엔트리에서 `0x0000`을 유효한 전각 공백 토큰으로 바꾸고, 마지막 연속 제어 토큰 전체를 분리해 그 앞을 채웠다. 길이 초과 입력은 종료자 공간을 먼저 확보하고 문자·제어 토큰 단위로만 잘랐으며, 오류 글리프와 제어 접미부 손상이 사라지는지 해당 소비 경로에서 대조했다.
- **확정 결과:** 이 고정 2바이트 경로는 유효한 공백 토큰, 완전한 trailing control sequence, 종료자 예산과 토큰 단위 절단을 함께 보존해야 했다.
- **전이 한계:** 공백·종료자·토큰 폭은 소비자에서 다시 정한다. 토큰 단위 절단도 의미 보존을 보장하지 않으며 릴리스 기본 정책으로 삼지 않는다.
- **관련 판단 기준:** `references/strategy/text-extraction.md`, `references/strategy/reinsertion.md`, `references/conventions/data-formats.md` §5.
