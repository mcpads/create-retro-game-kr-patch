# Dreamcast 국소 사례

## DC-001

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 중첩 스크립트 항목.
- **사고 맥락:** 재배치 코드가 각 장면을 `다음 장면 포인터`까지만 잘랐다. 실제로는 여러 진입점이 뒤쪽 대사와 인물 표시 제어코드를 공유해 앞 장면도 같은 종료자까지 읽어야 했다.
- **결정 실험:** 각 장면 시작점에서 실제 종료자를 찾아 다음 장면 시작보다 뒤에 놓이는지를 전수 비교했다.
- **확정 결과:** `다음 장면 포인터`는 끝 경계가 아니었고 여러 장면이 같은 종료자까지의 뒷부분을 공유했다.
- **전이 한계:** 중첩 여부는 각 시작점에서 실제 종료자까지의 소비 범위로 판정한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §1.3.

## DC-005

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 음성 동반 대사창과 대기·전환 제어코드.
- **사고 맥락:** 한국어 표시 글리프 수가 줄어 후반 음성이 점점 일찍 끊겼고, 장면 데이터의 남는 공간을 공백으로 채워 원문 크기에 맞추는 방안이 먼저 제안됐다.
- **검증 근거:** 소비자를 역어셈블해 전환 코드 뒤의 바이트를 읽지 않음을 확인했다. 대기값을 늘린 대조 실험과 장면별 실제 실행에서 표시 간격과 음성 잘림이 함께 변했다.
- **확정 결과:** 이 경로의 대사창 시간은 저장 바이트 길이가 아니라 대기 프레임과 행별 글리프 표시 시간으로 결정됐다. 소비되지 않는 끝 패딩은 버리고 부족해진 표시 시간만 장면별 대기값으로 보정했다.
- **전이 한계:** 보정량은 대기·행 구성과 실제 음성 경계를 장면별로 측정해 정한다.
- **관련 판단 기준:** `references/strategy/text-extraction.md` §3.1·§3.2, `references/strategy/translation-workflow.md` §4, `references/strategy/build-and-verify.md` §4.

## DC-006

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 옵션 타이틀 엔진 코드와 리터럴 풀.
- **사고 맥락:** 생성기가 코드 배치를 정하도록 바꾼 뒤에도 남아 있던 고정 주소 직접 쓰기가 새 위치의 리터럴 풀을 덮었다.
- **검증 근거:** 최종 바이너리에서 생성 결과와 수동 쓰기 범위를 대조해 두 쓰기가 같은 범위를 바꾸는 것을 확인했다.
- **확정 결과:** 예전 고정 주소 쓰기를 제거하고 생성기만 해당 범위를 쓰게 하자 리터럴 풀 손상이 사라졌다.
- **전이 한계:** 다른 레이아웃은 최종 산출물에서 각 쓰기 범위와 겹침을 다시 판정한다.
- **관련 판단 기준:** `references/strategy/build-and-verify.md` §1, `references/conventions/project-conventions.md` §5.2.

## DC-007

- **관측 범위:** Dreamcast판 뿌요뿌요~n의 데이터 트랙 파일 재배치와 오프닝 동영상.
- **사고 맥락:** 큰 파일 간격을 빈 공간으로 본 추정이 데이터 파일 사이의 간격을 잘못 분류해, 재배치 파일을 뒤쪽 동영상과 겹치는 위치에 썼다.
- **검증 근거:** 루트 디렉터리의 모든 LBA 구간과 재배치 결과를 대조해 동영상 구간 침범을 확인했다. 디렉터리에 기록된 마지막 점유 구간 뒤로 옮긴 빌드에서 오프닝을 실제 재생했다.
- **확정 결과:** 이 이미지에서는 디렉터리에 기록된 모든 파일 구간을 공간 점유로 계산한 뒤에만 새 파일을 배치해 동영상 덮어쓰기를 제거했다.
- **전이 한계:** 이 배치는 디렉터리가 점유 영역을 완전히 기술하고, 트랙·볼륨 경계와 연속 공간 조건을 만족할 때만 성립한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §5, `references/strategy/build-and-verify.md` §2·§4.

## DC-008

- **관측 범위:** Dreamcast판 사쿠라 대전 2의 한 스토리 대사 화면과 세 크기의 폰트 자산.
- **사고 맥락:** 작은 폰트의 선행 실험과 파일명을 근거로 스토리 대사도 같은 폰트를 쓴다고 보았고, 한 크기에서 계산한 슬롯 번호를 다른 크기에도 적용하려 했다.
- **검증 근거:** 세 시트의 넓은 범위에 크기별로 다른 표식을 넣어 32픽셀 폰트가 실제 사용됨을 가려냈다. 각 시트를 따로 디코드하자 같은 문자도 슬롯이 달랐다.
- **확정 결과:** 관측한 대사는 한 바이트에 두 픽셀을 담는 4bpp 고정 셀의 32픽셀 폰트를 사용했으며, 같은 문자도 시트 크기마다 슬롯이 달랐다.
- **전이 한계:** 다른 화면은 실제 사용 폰트와 해당 시트의 코드→글리프 대응을 각각 다시 입증한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md`, `references/strategy/runtime-assets.md`, `references/strategy/poc.md`.
