# PC-98 국소 사례

## PC98-001

- **관측 범위:** PC-98 마도물어의 게임 고유 Shift_JIS 계열 소비자.
- **사고 맥락:** 표준 CP932로 디코딩되는 바이트 조합만 센 통계는 선행 바이트 `0xEB`를 미사용으로 보았다. 실제 원본에는 표준 디코더가 거부하는 게임 고유 조합이 존재했다.
- **결정 실험:** 파서가 도달 가능한 원본 전체에서 2바이트 조합을 전수 집계해 게임 고유 조합을 예약하고 한글 인코더가 이를 만들지 않는지 검증했다.
- **확정 결론:** 선행 바이트 `0xEB`에는 표준 CP932가 거부하지만 게임이 실제로 사용하는 조합이 있어 빈 코드 공간이 아니었다.
- **전이 한계:** 이 결과는 2바이트 직접 코드 공간에만 적용한다. 다른 길이의 이스케이프 표현은 따로 산정한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §2, `references/platforms/pc98.md` §5.

## PC98-002

- **관측 범위:** PC-98 마도물어 A·R·S의 확장 글리프용 JIS→Shift_JIS 변환과 JIS 행 `0x75`·`0x76`의 94칸 전수 표시.
- **사고 맥락:** 홀수 JIS 행의 경계식이 칸 `0x5F`를 금지된 후행 바이트 `0x7F`로 만들었다. 자형 생성기와 검증기도 같은 경계값 오류를 공유해 두 결과의 일치만으로는 오류를 찾지 못했다.
- **검증 근거:** 각 칸의 위치가 보이는 표식을 한 행의 94개 코드에 넣고 항상 재현할 수 있는 전투 메시지 경로로 표시했다. 홀수·짝수 행의 94칸을 모두 확인하면서 `0x5F→0x7E`, `0x60→0x80` 경계를 바로잡았고, 금지값 전수 검사와 생성 산출물 재검사를 추가했다.
- **확정 결과:** 같은 공식을 공유하는 생성기와 검증기의 합의 대신 허용 입력의 경계값 검사와 실제 소비자의 전수 표시를 결합해 오류를 해소했다.
- **전이 한계:** 같은 변환식을 공유하는 생성기와 검증기의 일치만으로 인코딩 경계를 확정하지 않는다. 새로 사용하는 행·칸은 금지값과 경계값을 독립적으로 전수 검사하고 실제 소비 경로의 표시와 대조한다.
- **관련 판단 기준:** `references/strategy/font-strategy.md` §2·§4, `references/strategy/build-and-verify.md` §4·§5.

## PC98-003

- **관측 범위:** PC-98 마도물어 A·R·S의 엔딩 크레딧과 빈 항목을 나타내는 값이 섞인 워드 포인터 표.
- **사고 맥락:** NUL 사이 간격을 개별 고정 슬롯으로 보면 긴 한국어 크레딧을 수용할 수 없었다. 실제 소비자는 빈 항목을 나타내는 값이 섞인 포인터 표의 주소에서 각각 진입했다.
- **검증 근거:** 유효 포인터 대상과 갱신 위치를 전수 연결하고 문자열을 경계가 확정된 기존 영역 안에 다시 배치해 포인터 값을 갱신했다. 오버레이 크기와 뒤따르는 코드를 보존하고 표시와 다음 표 항목 진행을 확인했다.
- **확정 결과:** 개별 원본 간격 대신 참조 관계가 독립 진입을 보장하는 전체 영역을 재삽입 용량으로 사용해 긴 항목을 축약하지 않고 수용했다.
- **전이 한계:** 이 용량 산정은 모든 진입 포인터·빈 항목을 나타내는 값·항목 폭과 뒤 구조 경계가 확인된 영역에만 성립한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §1.2·§2·§3, `references/strategy/build-and-verify.md` §3·§4.

## PC98-004

- **관측 범위:** PC-98 마도물어에서 크기가 늘어난 여러 데이터 구간과 그 뒤의 포인터·디렉터리·구조 주소.
- **사고 맥락:** 각 구간을 따로 늘리면 안전해도, 앞선 삽입 뒤의 위치를 다음 변경의 기준으로 쓰거나 포인터가 저장된 위치와 포인터가 가리키는 주소에 같은 이동량을 적용하면 여러 변경을 합친 결과에서 보정이 빠지거나 중복될 수 있었다.
- **검증 근거:** 모든 변경은 원본 위치를 기준으로 계획하고, 크기가 늘어나는 구간은 원본 오프셋의 역순으로 적용했다. 포인터가 저장된 위치와 가리키는 주소의 누적 이동은 따로 계산했으며, 헤더 디렉터리와 뒤쪽 구조는 최종 위치로 한 번만 고쳤다. 구조 재감사, 디스크 재추출 일치와 두 증가 구간의 표시·분기·RAM 포인터로 결과를 확인했다.
- **확정 결과:** 원본 위치를 기준으로 역순 적용하고 포인터 저장 위치와 가리키는 주소의 이동을 따로 계산하자 각 위치 의존 구조를 정확히 한 번씩 옮길 수 있었다.
- **전이 한계:** 역순 적용은 원본 기준의 여러 가변 구간과 뒤따르는 위치 의존 구조가 확인된 경우에만 후보로 쓴다. 새 입력에서는 각 구간의 참조·내부 기준점·구조 주소·고정 수치와 적재 용량을 다시 열거한다.
- **관련 판단 기준:** `references/strategy/reinsertion.md` §1.2·§2·§3, `references/strategy/build-and-verify.md` §3·§4.
