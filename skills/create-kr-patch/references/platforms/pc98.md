# NEC PC-98

Fix the target PC-98 model before consulting primary references for CPU, BIOS, and disk specifications. Keep execution addresses, display paths, disk containers, and filesystem layers distinct.

## 1. Execution and display paths

Converting runtime segment:offset to file location requires the actual loader and the file or sectors loaded by DOS or BIOS I/O. Do not transfer a real-mode relationship to later protected-mode or 32-bit paths or to another module.

The text plane, system font or external characters, font-hardware-to-graphics copies, custom bitmap renderers, and baked graphics text may be separate consumers. Do not generalize one external-character PoC or stored bitmap to a common font path for dialogue, menus, and battle.

## 2. D88 containers

D88 preserves track and sector metadata and is not equivalent to a sector-data-only raw image. Do not choose a 160- or 164-entry track-offset table from the first offset alone. Test all nonzero offsets, sector chains, and declared disk size for file-wide consistency under each candidate.

Sector size code and header data-length field may disagree, and the latter may be unreliable in a target image. Cross-check N, next sector or track boundary, and file extent to determine stored size. Preserve raw C/H/R/N, sector count, density, deleted and status values, and data length. Do not normalize interleave represented by sector order or unformatted tracks. Verify every supported representation through unchanged round trip across the target image population.

## 3. Raw floppy and HDI layers

A headerless raw floppy may not have unique geometry from file size alone. Cross-check BPB, media geometry, and the actual loader, and include metadata synthesized or lost by raw-to-D88 conversion in distribution conditions.

`.hdi` conventionally identifies a PC-98 hard-disk image container with a header and geometry. A headerless floppy raw file distributed with that extension is mislabeled input, not another HDI format. Reassess actual format when extension and internal structure disagree.

The HDI header belongs to the container. IPL, partition tables, and FAT are disk contents inside it. When supporting an HDD path, verify target BIOS, device interface such as SASI, IDE, or SCSI, geometry, boot partition, and real device path separately.

## 4. Filesystem and sector units

Determine FAT type and sector or cluster size from actual BPB and cluster count, not disk capacity or extension. When physical and BPB logical sectors differ, establish the converting layer and the unit consumed by the loader.

File growth or movement must update every referenced directory, FAT chain, duplicate FAT, free allocation, and game-specific sector or file table. A valid filesystem does not prove that a raw-track reference or custom loader is correct.

## 5. Text and Hangul code space

Establish character encoding and script representation through the actual dispatcher, glyph lookup, and screen consumer. A game-local Hangul code applies only to consumers that interpret it.

Judge code-space reuse, total repertoire, and active working sets through `references/strategy/font-strategy.md`.
